## DESIGN PHILOSOPHY

### Core Principles
1. **Function over Aesthetics** - Kecantikan tanpa fungsi adalah kegagalan
2. **Validate Everything** - Setiap keputusan harus punya alasan
3. **User First, Business Second** - Happy users = happy business
4. **Less is More** - Simplicity is the ultimate sophistication
5. **Consistency is Key** - Design system bukan optional

### Design Values
- **Clarity** - Desain harus jelas, bukan membingungkan
- **Confidence** - User harus yakin dengan aksi mereka
- **Comfort** - Experience harus menyenangkan
- **Capability** - User harus bisa mencapai goals mereka

### Color Accessibility

#### Contrast Ratio Requirements (WCAG 2.1)
- **Normal text (< 18px)**: Minimum 4.5:1
- **Large text (≥ 18px or 14px bold)**: Minimum 3:1
- **UI Components**: Minimum 3:1
- **AAA Level**: 7:1 for normal text

#### Color Blindness Considerations
- Don't rely on color alone for meaning
- Use patterns, icons, or labels as secondary indicators
- Test with Coblis or similar color blindness simulator
- Common types: Protanopia (red), Deuteranopia (green), Tritanopia (blue)

## DESIGN VALIDATION CHECKLIST

### Before Finalizing Any Design

#### Visual Hierarchy
- [ ] Is the most important element most visible?
- [ ] Does the eye flow naturally through the design?
- [ ] Are headings clearly differentiated from body text?
- [ ] Is there enough whitespace?

#### Color
- [ ] Does the color palette match the brand/personality?
- [ ] Are semantic colors used appropriately?
- [ ] Is there sufficient contrast for accessibility?
- [ ] Does it work in both light and dark mode?

#### Typography
- [ ] Is the font readable at all sizes?
- [ ] Is the line length appropriate (45-75 characters)?
- [ ] Is line-height comfortable for reading?
- [ ] Are heading styles consistent?

#### Spacing
- [ ] Is spacing consistent throughout?
- [ ] Are related elements grouped together?
- [ ] Is there enough touch target size (44x44px minimum)?
- [ ] Does the layout breathe?

#### Interaction
- [ ] Are all interactive elements obvious?
- [ ] Are hover/focus states defined?
- [ ] Are loading states considered?
- [ ] Are error states handled gracefully?

#### Responsiveness
- [ ] Does it work on mobile (320px+)?
- [ ] Does it work on tablet (768px+)?
- [ ] Does it work on desktop (1024px+)?
- [ ] Does it work on large screens (1440px+)?

#### Accessibility
- [ ] Can everything be navigated by keyboard?
- [ ] Are alt texts provided for images?
- [ ] Is the tab order logical?
- [ ] Are ARIA labels used appropriately?

## COMMUNICATION FRAMEWORK

### When Presenting Design

#### Structure
1. **Context** - Background, goals, constraints
2. **Problem** - What we're solving
3. **Solution** - The design approach
4. **Rationale** - Why this solution
5. **Validation** - How we know it works

#### Language
- Use specific, not vague terms
- Reference data and research
- Acknowledge alternatives considered
- Be open to feedback

### Sample Communication

#### Instead of:
> "I made this blue because it looks nice."

#### Say:
> "I chose this blue (#3B82F6) for the primary CTA because:
> 1. It aligns with our brand color palette
> 2. Blue conveys trust, which is crucial for a finance app
> 3. It has a 4.5:1 contrast ratio against white, meeting WCAG AA
> 4. A/B testing on similar projects showed 15% higher click-through compared to green"

### Feedback Framework

#### Giving Feedback
1. **Observation** - What I see
2. **Impact** - How it affects the experience
3. **Suggestion** - What could be improved
4. **Question** - Open for discussion

#### Receiving Feedback
1. Listen fully before responding
2. Ask clarifying questions
3. Acknowledge valid points
4. Explain reasoning if needed
5. Commit to action items
