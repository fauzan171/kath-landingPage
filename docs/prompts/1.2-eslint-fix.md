## Critical Errors (Must Fix First)

### Error 1: Impure Function in Render 🔴

**File:** `src/components/ui/sidebar.tsx`
**Line:** 611
**Rule:** `react-hooks/purity`

**Error:**
```
Error: Cannot call impure function during render

`Math.random` is an impure function. Calling an impure function can produce 
unstable results that update unpredictably when the component happens to re-render.
```

**Current Code:**
```typescript
const width = React.useMemo(() => {
  return `${Math.floor(Math.random() * 40) + 50}%`
}, [])
```

**Why This is Wrong:**
- `Math.random()` is impure - it returns different values each time
- Even in `useMemo`, this violates React's purity rules
- Can cause hydration mismatches in SSR
- Can cause unpredictable re-renders

**Solution:**
```typescript
// ✅ Use useState with lazy initialization
const [width] = useState(() => `${Math.floor(Math.random() * 40) + 50}%`)
```

**OR:**
```typescript
// ✅ Generate outside component entirely
const generateRandomWidth = () => `${Math.floor(Math.random() * 40) + 50}%`;
// Then use in component
const width = useMemo(() => generateRandomWidth(), [])
```

### Error 2: setState in useEffect (AuthContext) 🔴

**File:** `src/contexts/AuthContext.tsx`
**Line:** 62
**Rule:** `react-hooks/set-state-in-effect`

**Error:**
```
Error: Calling setState synchronously within an effect can trigger cascading renders
```

**Current Code:**
```typescript
useEffect(() => {
  const storedUser = localStorage.getItem(CURRENT_USER_STORAGE_KEY);
  if (storedUser) {
    try {
      const parsedUser = JSON.parse(storedUser);
      setUser(parsedUser);  // ← setState in effect
    } catch (error) {
      console.error('Error parsing stored user:', error);
      localStorage.removeItem(CURRENT_USER_STORAGE_KEY);
    }
  }
  setIsLoading(false);
}, []);
```

**Why This is Flagged:**
- Calling `setUser()` inside useEffect can cause extra renders
- React prefers lazy initialization for this pattern

**Solution:**
```typescript
// ✅ Use lazy initial state
const [user, setUser] = useState<User | null>(() => {
  const storedUser = localStorage.getItem(CURRENT_USER_STORAGE_KEY);
  if (storedUser) {
    try {
      return JSON.parse(storedUser);
    } catch (error) {
      console.error('Error parsing stored user:', error);
      localStorage.removeItem(CURRENT_USER_STORAGE_KEY);
      return null;
    }
  }
  return null;
});

const [isLoading, setIsLoading] = useState(false);

// Remove the useEffect that was doing this
```

**Note:** This pattern is actually acceptable for auth initialization, but the linter flags it. Using lazy initialization is cleaner.

### Error 3: setState in useEffect (useApi.ts) 🔴

**File:** `src/hooks/useApi.ts`
**Lines:** 49, 88
**Rule:** `react-hooks/set-state-in-effect`

**Error:**
```
Error: Calling setState synchronously within an effect can trigger cascading renders
```

**Current Code:**
```typescript
const fetchData = useCallback(async () => {
  setState(prev => ({ ...prev, loading: true }));
  try {
    const response = await api.get(endpoint);
    setState(prev => ({ ...prev, data: response.data, loading: false }));
  } catch (error) {
    setState(prev => ({ ...prev, error, loading: false }));
  }
}, [endpoint]);

useEffect(() => {
  fetchData();  // ← Called in effect with fetchData as dependency
}, [fetchData]);
```

**Problem:**
- `fetchData` is called in useEffect
- The dependency array has `fetchData` which may change
- This can cause unnecessary re-renders

**Solution:**
```typescript
// ✅ Proper dependency management
const fetchData = useCallback(async () => {
  // ... same logic
}, [/* stable dependencies only */]);

useEffect(() => {
  let cancelled = false;
  
  const load = async () => {
    try {
      const response = await api.get(endpoint);
      if (!cancelled) {
        setState(prev => ({ ...prev, data: response.data, loading: false }));
      }
    } catch (error) {
      if (!cancelled) {
        setState(prev => ({ ...prev, error, loading: false }));
      }
    }
  };
  
  load();
  
  return () => {
    cancelled = true;
  };
}, [endpoint]); // ← Only depend on endpoint, not fetchData
```
